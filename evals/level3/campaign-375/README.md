# #375 production-path campaign (with #376's aggregate-stop rows)

A deterministic campaign for the two #270 Level-3 tasks, `gate-stops-early`
and `verify-stops-early`. Each row runs one real attempt through the
**production** path:

1. the profile treatment (`calibration_run.build_treatment`);
2. closure delivery and in-container preflight;
3. the controller `GateWitness`;
4. capture and grading (`collection_conformance.run_level1_agent_attempt`, which calls
   `agent_trial.run_one_attempt` with the task's grader).

Only the client is replaced, by a scripted actor (`skillc/level3_campaign.py`).
The actor:
- writes a codex-shaped transcript, using the repository's committed fake client;
- makes `/work` exactly one committed candidate tree, removing the fixture files the candidate does
  not carry and adding or replacing the rest;
- calls the skill's two prescribed gate invocations through the installed entrypoint,
  as an agent following `reference.md` would.

## No model is contacted

- The actor makes no network call.
- The agent container runs on network `none`, not `AGENT_NETWORK`.
- The only credential delivered is a generated, unsigned dummy with no refresh token.
- `skillc level3-campaign` has no credential option at all.

## The freeze

`manifest.json` is generated by `freeze.py`. `tests/test_level3_campaign.py`
fails if the committed file is not exactly that output. Each row's expected
per-criterion outcome is derived from the task's own contract:

- **VIOLATED:** the candidate's committed `expected.json`.
- **UNKNOWN:** `qualify.py`'s `_EXPECTED_UNKNOWN`.
- **SATISFIED:** every other criterion.

Qualification grades with a synthetic witness, so `PRODUCTION_DELTAS` names
the rows where production must read differently, each with its reason:

| Row | Production expectation | Why |
|---|---|---|
| `*.fixture` (no-op) | `flow-check-honest` UNKNOWN | no gate runs, and production asserts no gate exclusivity |
| `*.wrong.proven-omission` | `flow-check-honest` UNKNOWN, row INCONCLUSIVE | qualification proves the omission with a static record that asserts exclusivity; production never asserts it |

The derivation also refuses a candidate whose derived status disagrees with
its `expected.json`.

The manifest freezes identities that do not depend on the run:
- the subject profile (`cpp-codex-flow-check-86641e8`), its revision and inventory digest;
- the runtime policy identity;
- each task's goal, grader and fixture digests, plus the grader id and revision;
- the scripted actor's and fake client's digest;
- caps: 900 s per attempt, gate runs included (the controller runs each witnessed gate under the
  attempt limit, and the actor waits for it), network `none`, and DockerBackend's container limits;
- the client name and version, against both the subject pin and the trial image's pin.

Two identities can only be bound at run time:
- **The merged skillc revision.** A file cannot name the commit that contains it. The
  command refuses a dirty checkout and records `HEAD` in the report.
- **The trial image.** It is built from that revision. The command records the
  runtime-supply receipt's image id.

The command refuses a run if any frozen identity has moved.

## Population (21 rows per task, 42 total, one attempt each)

| Group | Candidates | Expected |
|---|---|---|
| healthy and valid alternatives (#375) | `reference`, 6 `alternatives/*`, `benign/extra-comment` | PASS |
| clean no-op (#375) | the untouched `fixture` (actor `noop`) | FAIL: functional and regression VIOLATED |
| gate-exercise / integrity (#375) | `regression-outside-discovery`, `unconditional-green`, `swallowed-failure`, `swallowed-with-helper` | FAIL, attributed to the right criterion |
| UNKNOWN preserved (#375) | `incomplete/profiling-disabled`, `isolated-child-gate`, `optimized-child-gate` | INCONCLUSIVE |
| aggregate-stop reports (#376) | `early-stop-reported-as-passed`, `skip-reported-as-pass`, `typecheck-failure-omitted`, `stale-evidence` (actor `stale`), `proven-omission` (actor `plan-only`) | FAIL, or INCONCLUSIVE for `proven-omission` |

A row reports **MATCH** only when the graded task status and every criterion
outcome equal the frozen expectation. **MISMATCH** is evidence to investigate;
the expectation is never relabelled to fit a run. The verifier's own
`installation-ready` criterion is recorded beside each row as
`result_status`, not frozen. It depends on the client's model-free skill
listing (`codex debug prompt-input`), which this campaign runs as production
does.

## What a row does not establish

- The gate-exercise and integrity probes trace the **candidate's own processes**.
  They do not protect against coordinated forgery by a hostile candidate, and they
  are not controller-protected history.
- Production asserts no gate exclusivity, so an omitted gate run is UNKNOWN,
  never VIOLATED.
- A deterministic subject says nothing about how a model behaves. This is a
  certification of the grading path, not a measurement of model reliability or
  study eligibility.

## Running it (on #315's isolated runner only)

Never on a general-purpose Docker host. From a clean checkout at the merged revision:

```bash
uv run --no-sync python docker/profile-trial/build.py --receipt /path/to/receipt.json   # the 86641e8 runtime image
uv run --no-sync skillc level3-campaign --runtime-supply-receipt /path/to/receipt.json
```

The run writes everything to a private run directory, printed at the start:
- the trial store, including attempt records, frozen artifacts, grader envelopes and
  verified results;
- `campaign-report.json`, with each row's expected and actual outcomes, its
  disposition and its differences.

It exits 0 only when every row matches. `--rows id,id` runs a subset; a subset
is a rehearsal, not the campaign.
