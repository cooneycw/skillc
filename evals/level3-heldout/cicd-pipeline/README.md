# Held-out instance: cicd-pipeline (#281)

The sealed second instance of `evals/level3/cicd-pipeline`: a different
claude-power-pack `/project:init` Python project (`ledger-tool`: two modules,
`[tool.mypy] files = ["src"]`, Woodpecker-only), generated by
`scripts/project_init_fixture.py generate heldout`.

**How it stays sealed.** It lives here, outside the task directory, so nothing
the agent is given (`goal.md`, the task's `fixture/`) and nothing a dev
iteration grades against (`reference/`, the candidates) is under this path.
`tests/test_level3_cicd_pipeline.py::test_the_agent_surface_carries_no_heldout_bytes`
fails if the task's goal, inputs, probe, fixture or reference carry its name or
any of its source files' bytes. The grader's judge holds only digests of its
starting files (to check preservation), never its contents, and the judge is
never shown to the agent.

It is graded only by the full certification (`qualify.py --full`, run by
run-real-docker on evals26): its `fixture/` must FAIL and its `reference/` must
PASS, with the same judge and the same pinned tools (`uv.lock` resolves exactly
the dev instance's ruff/pytest/mypy, which a test asserts).
