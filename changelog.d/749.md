- **`contract-shape` counts the intent's id, and `charter draft` follows CommonMark fences** (#749, deferred from #726 PR A's review). An intent and another clause sharing one id is now a `contract-shape` error. Before, a single owner answer could approve both, and `charter confirm` refuses any draft that fails contract-shape. A code fence now closes only on the same character at least as long, with no info string. It may be indented up to 3 spaces, and an unclosed fence runs to the end of the file. So a fenced example nested in a longer fence no longer turns into a proposed duty. contract-shape is stricter: none of the 53 CHARTER.md files committed before this change reused its intent id.
