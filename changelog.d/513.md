- **An independent-tier judge over the Anthropic Messages API** (#513). `skillc/judge_anthropic.py` adds `AnthropicJudge`, a stdlib `Judge` that calls the Messages API directly with a forced tool whose input schema is the judge-verdict schema. ADR 0005 section 4 is amended to permit it, quoting the owner's ruling.
  - The model is pinned to `claude-opus-5-5`. The key is read controller-side from an AWS Secrets Manager secret at call time. A no-leak red covers both the success path and the provider error path, and a static check keeps the judge out of every container-path module.
  - Requests over the size cap are refused, not truncated. A redirect is never followed, so the key cannot follow one to another host; a malformed HTTP reply is `JudgeUnavailable` rather than an escaped exception; and the rubric definitions sent are leak-checked before the key is read. A reply that is not exactly one forced-tool call, a timeout, a 4xx or 5xx, or an oversize reply gives `JudgeUnavailable` or a malformed verdict, never a fabricated one. Every test drives the committed `FakeMessagesServer`; none makes a real call.
  - `primary_endpoint.tier` in a live fixture declaration is `deterministic` by default. `independent` requires a `judge` block: model, secret id, `max_tokens`, `calls`, and a price with its source URL and the date it was read. The declaration is refused when its worst case (every call at the request cap and `max_tokens`) exceeds the $5 ceiling. An unknown tier, an unknown key and a judge block under the deterministic tier are refused too. `run_live` refuses an independent-tier declaration, because no judge is wired into the live path.
  - `evals/level3/flow-auto-necessity/qualify_judge.py` proves the plumbing on the 98 committed candidates and refuses three broken-judge controls. It prints PLUMBING ONLY: it is not the paid held-out validation, which still needs the owner's approval.
