# 0.3.0

Delivers three milestones, all closed: [#12](https://github.com/cooneycw/skillc/issues/12),
the first predeclared matched pilot with a clean evidence bundle;
[#124](https://github.com/cooneycw/skillc/issues/124), the Claude Code agent
arm; and [#122](https://github.com/cooneycw/skillc/issues/122), real-daemon
seeds for timeout and operator cancellation. All three were proven on the
operator's own machine. Full detail:
[`CHANGELOG.md`](https://github.com/cooneycw/skillc/blob/v0.3.0/CHANGELOG.md)'s
`[0.3.0]` section.

## #12: the first predeclared matched pilot

`skillc pilot-run`/`pilot-report` ran the predeclared schedule
(`evals/matched-pilot/run-manifest.json`): codex on the Level 1
`slug-small-fix` task, the whole `cpp-codex` pack installed (treatment) or
nothing (baseline), 3 repeats interleaved T,B,T,B,T,B, one disclosed protocol
deviation on the first run - the run declared `gpt-5.1-codex` but nothing
pinned it at launch, so all six attempts ran codex's own default,
`gpt-6-astra` (#141 now pins the declared model at launch and refuses a run
that did not use it).

**The pinned re-run is the clean evidence** ([#147](https://github.com/cooneycw/skillc/issues/147),
`evals/matched-pilot/evidence-2026-09-27-gpt-6-astra/`, commit `422f9d2`):
a new experiment (`matched-pilot-64396611`) under the `gpt-6-astra`
declaration. All 6 attempts were captured and graded PASS; every attempt ran
the declared model at effort `high`, no protocol deviation, no attempt ruled
ineligible. `skillc check-records` reports 0 errors. Reviewed claims: 6 of 6
accurate, 0 interventions. The first run's bundle is unchanged, still in
`evals/matched-pilot/evidence/`, as the disclosed-deviation record it always
was.

**Three record-level gaps #12 could not have proven closed on any run,
fixed alongside it** (PR #151): the image id a Docker attempt's container
was actually created from is now journalled beside the ledger's planned
digest, so a floating or republished tag is no longer assumed to be what
ran; a judge verdict now records the LLM that actually answered
(`judge.model`), not the MCP server's own name (`judge.server`) - two tiers
on one server can now record two different models; and grading now holds an
experiment lock across snapshot, grade, retry and stored records, so a
sibling attempt legitimately capturing mid-grade no longer falsely refuses
the grade.

**What #12 does not establish**: one bounded pilot, one task, one client, no
baseline arm beyond "nothing installed" - equal or better results on this
task say nothing about whether a collection helps on harder or different
work. Judge/model dollar cost is `UNKNOWN` under the operator's own
subscription login (ADR 0005 rule 6); no paid model trial has been
authorized or made by anything in this repository.

## #124: the Claude Code agent arm

A second client arm, alongside the existing codex arm, proven with the same
discipline #11 already established for a second skill collection: `skillc
collection-run` now takes its client and default argv from the subject
(`claude -p --dangerously-skip-permissions` as the non-root trial user), and
two new subjects exist - `cpp-claude-code` (CPP's native `.claude/skills`,
18 skills) and `mattpocock-skills-claude-code` (`tdd`, `diagnosing-bugs`).

Claude Code has no model-free listing the way codex does, so discovery is
read from the real agent transcript's own `skill_listing` attachment
instead - `UNMEASURED` with a stated reason wherever a listing wasn't
observable (which is every codex run; discovery there is never borrowed from
a different client's canary result). **Both collections were run live**
(`evals/claude-code-agent-arm/`): the first runs surfaced a defect - a blind
`refresh_observed_in_container=None`, fixed under #106's own key-name fix -
and were repeated afterward on the corrected key, both reading `False` (no
credential refresh observed).

## #122: real-daemon seeds for timeout and operator cancellation

The two failure paths judged most likely to differ between the fake `docker`
CLI and a real daemon now have committed red cases (`skillc demo --control`,
seeds 5-6) and were run live on native Docker Engine 29.8.1: a timeout
(`sleep 30s`, 3s limit) stopped as `timeout`, confirmed via `docker inspect`,
disposition `inconclusive`, reaped `already-absent`; and a real `SIGINT`
mid-exec printed the fixed interrupt line, exited `1`, cleaned up only its
own attempt (a foreign container was left running, then independently
confirmed removed). Five other honesty gaps in `demo`/`--control`, found
reviewing this work (folded in from the Nit Store, #20), are fixed alongside
it - each with its own red case (a reply-only control that accepted any
failure; a fleet check that could be silently omitted; a neighbour's
unrelated container change failing the run; the reap sweep missing the
grading probe's own attempt; a second Ctrl-C escaping as a raw traceback).

## What else shipped in this cycle

- **Level 2 and Level 3 calibrated task families** ([#13](https://github.com/cooneycw/skillc/issues/13),
  still open - see below; PR #168): `evals/level2/slug-constrained/` (three
  public constraints - interface stability, a dependency restriction, data
  preservation - each its own criterion) and `evals/level3/slugkit-installed/`
  (a real installed-consumer defect class, graded through a stdlib-only
  install emulation since neither pip nor a build backend exists in this
  dev environment or the trial image). Both self-certify; neither has run
  through a live agent.
- **An optional managed-container backend, client-only** ([#64](https://github.com/cooneycw/skillc/issues/64),
  still open; PR #165): `skillc.managed_backend.ManagedBackend` and a newly published
  protocol (status "Proposed") for a platform that manages its own
  containers to run a trial without skillc depending on it. No platform
  implements the protocol yet; a first intended implementer is tracked as
  [cooneycw/kyle#1397](https://github.com/cooneycw/kyle/issues/1397), a
  different project.
- **`skillc degrade-subject` and `collection-run --degraded`/`--evidence`**
  ([#150](https://github.com/cooneycw/skillc/issues/150), still open): an
  operator-expressible degraded CPP subject (a collection with named skills
  or files removed/overridden, persisted as a digest-verifiable tree), a
  matching install path, and a leak-checked export of a graded verified-result
  to CPP's own behavioral-eval consumer. `finish-close-ref` gains a degraded
  arm (`evals/level1/finish-close-ref/degraded/`) built from committed facts
  about five files at a pinned revision, never vendored CPP text. An agent-
  path installation receipt and the operator's own runbook for the
  discriminating run landed too (150-D, see below) - see "What 0.3.0 is
  not" for exactly what's still owed.
- **`skillc selection-probe [--detection-control]`** ([#26](https://github.com/cooneycw/skillc/issues/26),
  still open): the operator command, the real `AttemptRunner` driver, and
  transcript retention (leak-checked before it is kept, the reason naming
  only a finding's class and line, never the matched value). The command
  and the detection-control mechanism were exercised live separately
  (`evals/selection-probe/evidence/README.md`); transcript retention landed
  afterward (#163) and has not yet been exercised in the SAME live run as
  the detection control - see "What 0.3.0 is not" below for exactly what's
  still owed. `records.ledger_binding` also gained a coverage check a Nit
  Store finding named: a `coverage: "complete"` skill-invocations stream
  could omit an installed skill's row and still pass clean.
- **Every real-agent attempt persists an `agent-observation` record**
  (#106, closed): prompt delivery, canary, skill invocations, the
  transcript census, credential delivery/refresh, and the grading account,
  all on disk instead of only in memory and a printed paste-back - the gap
  that cost #124 two repeated live runs when a field misprinted once.
- **A graded agent-trial attempt now stores its `verified-result`**
  (#139, closed; PR #146): `agent_trial.run_one_attempt` grades through the
  verifier's own result assembler instead of a bare `verify.grade_files`
  call, so the result keeps the ledger's grader pin, the capture check, and
  the frozen-digest checks - `attempt-accounting` no longer reports every
  captured agent attempt as "grading is still owed." The agent path writes
  no installation receipt (the baseline arm installs nothing), so its
  `agent-observation` record stands in for one, `installation-ready` stays
  UNKNOWN, and readiness still gates PASS. This is the same B1 stand-in
  150-D (#172) narrows for an installing arm specifically.
- **`make verify` and a real `## Verify` command** (#134, closed; PR #156),
  covering every `.woodpecker/ci.yml` step locally, plus a `pytest-timeout`
  gate with a 120s per-test default and a fuller CI log (#148, closed;
  PR #152) after a stalled test hung a CI pipeline 35+ minutes past a
  blocking write with nothing to diagnose afterward.
- **Docker backend hardening** (#133, closed; PR #164): a bounded
  `prepare()` with an explicit image precheck (an implicit image pull
  otherwise had no time bound at all), per-entry install readiness instead
  of all-or-nothing, and `ExecuteResult` now distinguishes an incomplete
  capture (a descendant process still holding the pipe open) from a merely
  truncated one.
- **Static-checker precision** (#131/#132, both closed; PRs #166, #167):
  `check-records` now reads a single file path correctly and refuses a
  `--rule` run whose applicable population is empty rather than reporting a
  vacuous "0 errors"; a new rule catches Claude Code's real combined-field
  listing cap; `rules` can show target-varying behaviour, not only
  target-restricted rules; `ref-depth` no longer double-reports one chain
  under two spellings of the same file; and `required-fields` now owns the
  type of the optional fields it reads, not only the required ones.
- **`leak-check` sees a checkout under `/workspace`, `/opt` or `/srv`**, not
  only `/home`/`/Users`, and no longer false-positives on a linked
  worktree's `.git` pointer file (#134 items 4-5, closed; PR #154) - every
  session in this fleet's own checkout previously went unflagged by its own
  leak scan.
- **A declared run state could hide a failed result** (#130, closed):
  `derive_status` honoured a declared `UNAVAILABLE`/`NOT_RUN` before
  checking criteria, so a result with a mandatory `VIOLATED` criterion could
  be relabelled `UNAVAILABLE` and pass `check-records`. The violation is now
  tested first.
- **The mcp-second-opinion judge could block past its write deadline**
  (#129, closed): a full pipe made a blocking write wedge forever; the write
  loop now runs non-blocking and keeps checking the clock.
- **Every backend attempt's lifecycle record said its workspace was never
  cleaned up** (#127, closed): finalization ran before cleanup, so a
  correctly-cleaned workspace still read `partial` - including #11's own
  live PASS runs.

## What 0.3.0 is not

- **Not a measurement of whether a collection, a degraded collection, or a
  skill selection helps.** #12's pilot, #124's live runs, and #150/#26's
  work all show mechanisms working and evidence being captured correctly -
  none of them is a comparison designed to answer "did this change the
  outcome," and none claims to be.
- **Not Level 2 or Level 3 run live.** #13's two new task families
  self-certify locally; no agent has attempted either yet, and #13 stays
  open for that run and for its "report functional/constraint/integration
  outcomes separately" evidence.
- **Not a real platform for the managed-container backend.** #64 ships a
  client and a published protocol; no platform implements it, and #64 stays
  open until one does.
- **Not #150's discriminating run yet - but everything it needs to run now
  exists.** Merged for #150: the `finish-close-ref` Level 1 task itself
  (#153); `degrade-subject`, an operator-expressible degraded CPP subject
  (#155); `collection-run --evidence`, the export path to CPP's
  behavioral-eval consumer (#157); `collection-run --degraded`, installing
  a persisted degraded subject (#160); `--task DIR` plus
  `finish-close-ref`'s own degraded-arm generator (#162); and 150-D
  ([PR #172](https://github.com/cooneycw/skillc/pull/172)), the
  agent-path installation receipt: `DockerBackend.execute()` runs once per
  container and stops it before returning, so the client's own model-free
  listing cannot run before/after delivery inside the agent's own
  container - it runs instead in a fresh, dedicated, throwaway container of
  the SAME IMAGE DIGEST, once with nothing delivered and once with the same
  tree delivered the same way. The receipt attests exactly that: this
  delivered tree, delivered by the same method, into a fresh container of
  the same image digest, was discovered - refused outright on any image or
  tree digest mismatch, and explicit that it does NOT attest the agent's
  own container had it. The operator's own ruling, quoted verbatim, and the
  limit it accepts (same-method delivery plus digest equality, never direct
  observation of the agent's own container) are both recorded in
  [ADR 0005](../decisions/0005-runtime-scope-and-cost-rulings.md).
  **Still owed, which is why #150 stays open**: the operator's own live
  discriminating run - the normal arm PASS and the degraded arm FAIL on
  `finish-close-ref`, codex arm, a positive control run first
  ([the runbook](../runbooks/150-discriminating-run.md)) - and then the
  export into claude-power-pack's own `docs/measurements/behavioral-eval/`
  through the CPP group. [claude-power-pack #1084](https://github.com/cooneycw/claude-power-pack/issues/1084)
  is blocked on that RUN now, no longer on a decision.
- **Not a real judge call or a paid model trial.** #12's own scope ruling
  continues to apply
  ([ADR 0005 rule 6](../decisions/0005-runtime-scope-and-cost-rulings.md)).
- **Not #28's configuration-boundary case delivery.** The eligibility survey
  ([an issue comment on #28](https://github.com/cooneycw/skillc/issues/28#issuecomment-5871614439))
  found no reproducible subject-behaviour failure in retained evidence to
  build a case from; the survey covered every retained source (both
  matched-pilot bundles, all task-PASS or task-criteria-SATISFIED, no
  attempt failed the task; four narrative-only sources naming no
  subject-behaviour failure). `docs/specs/evaluation-facility/configuration-boundary-example.md`
  (PR #161) delivers the issue's other half instead - a worked comparison
  against the six identity dimensions a trial ledger already records - and
  case delivery stays incomplete per #28's own stop condition; nothing was
  invented and no trial was run to manufacture a failure.
- **Not #55's own live evidence.** `skillc exposure` and its per-client
  renders already existed before 0.2.0; this cycle fixed four Nit-Store-
  sourced defects against #55's own acceptance criteria (#169): a
  `cut_point_bytes` byte-offset bug dormant on ASCII-only markers, a
  marker-boundary miscalculation that could misread a real cutoff as an
  exposure failure, a discovery-canary false negative on a correctly
  policy-hidden skill, and a new declared-vs-found manifest-coverage report.
  #55's own unchecked acceptance items (the surface-declaration layering
  signoff, a published evidence run against mattpocock/skills plus a
  synthetic truncation surface) are untouched by this cycle and remain
  owed.
- **Not #14's live run, and not its known gap closed.** Two planning-only,
  self-certifying case contracts now exist (#170), each certified by
  `qualify.py` and wired into pytest: Level 4 instruction conflict
  (`evals/level4/instruction-conflict-config-secret/` - the adversarial text
  confined to its own fixture, an obviously fake secret, a do-not-follow
  header) and Level 5 recovery (`evals/level5/recovery-partial-processing/`).
  Grading is deterministic against a structured `report.json` and an event
  log - no LLM judge. **A committed known gap, stated plainly, not hidden:**
  the log's provenance is a self-declared marker a subject that can write
  the log can forge; `known-gaps/forged-log/` in each case grades PASS today
  despite a real violation, and a test fails if that documented miss stops
  reproducing. Owed: the two runtime fixture services this needs (an
  authority-boundary interceptor and a disruption trigger), the verifier
  path that delivers the controller's log to the judge out of the subject's
  reach (closing the known gap), a real agent attempt, and calibration.
- **Not #15's qualification claim - and it makes none.** A docs-only method
  (#171, `docs/specs/evaluation-facility/level-qualification-method.md`)
  restates protocol.md §7's qualification requirement as a table of what
  each requirement needs and what the project has, applied once against the
  only real Level 1 data that exists (#12's matched pilot, 3 matched pairs,
  all task-PASS). **Verdict: Level 1 is `not evaluated`.** Three passes out
  of three support "no failure observed in three attempts," never a
  failure-rate estimate, and the population is one task, not a declared
  family - the same shape #13 and #14 are in too. Owed: pilot distributions
  for task families, none of which has been run.
- **Not #26's live run with retention.** The operator command, the detection
  control and transcript retention all exist (see above); still owed is a
  single live run that exercises the detection control AND retains
  transcripts together, on the operator's own host.
