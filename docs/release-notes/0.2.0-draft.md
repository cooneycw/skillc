# 0.2.0 (draft - not released)

**This is a draft, assembled ahead of time per [#72](https://github.com/cooneycw/skillc/issues/72)'s
release checklist, not the release notes themselves.** No version was bumped
and no tag was created to produce this file. 0.2.0 ships only when
[#10](https://github.com/cooneycw/skillc/issues/10) (a real Docker trial end
to end, run once against a real daemon on the operator's own machine) closes
on that live run - not before, whatever the code in this repository already
does. Until then this file is a working draft, refined as more of #10's own
work lands, so the actual release does not have to be written from scratch
under time pressure the day #10 closes.

## What 0.2.0 is

Everything the `[Unreleased]` section of [`CHANGELOG.md`](../../CHANGELOG.md)
already lists, in outline:

- The `ExecutionBackend` protocol (#10's seam, #65) and a lifecycle driver
  that exercises the full prepare/install/execute/confirm/export/destroy/
  finalize sequence with a per-attempt liveness canary (#70), plus an
  optional-backend grading path in `skillc/verify.py` (#76).
- `skillc/docker_backend.py`, the real Docker-backed implementation the seam
  was built for: composed `docker run` argv under fixed resource limits and a
  neutral non-root identity, ownership labels, and a documented conformance
  table against `interfaces.md`'s required cases (#77's interface and
  implementation - #83/#85; conformance - #80/#87).
- `skillc/reap.py`: label-scoped container reaping, before/after resource
  snapshots, and declared-host-path checks, plus a failure-path matrix
  stating every one of #10's addendum failure paths and which test proves it
  (#79/#91).
- The verified-result record contract's per-tier verdicts as a keyed
  collection (`verification.verdicts`, `verification.tiers_enabled`, a
  reserved `verification.disagreement`), with the deterministic tier as the
  only one that actually grades anything (#69/#88), and the judge seam
  itself (`skillc/judge.py`, #92) - schema-constrained output, a per-tier
  `UNAVAILABLE` outcome, a pre-send leak check - exercised only against a
  `FakeJudge`.
- `skillc exposure` (#55/#90): a rung-2 check of what actually reaches the
  model, per client, with no model call - planted markers, truncation
  detection, policy-hidden skills, and a blindness control.
- The trial ledger's `case.observes_selection` declaration and a pre-spend
  cost projection (#26/#39, #86), and a matched-pilot experiment record plus
  evidence-report schema (#12, #89), prepared for a treatment-vs-baseline
  comparison - the whole CPP pack installed versus a minimal baseline, on
  the same `slug-small-fix` task.

## What 0.2.0 is not

- **Not a real Docker daemon run.** Every claim above about the Docker
  backend - composed argv, resource limits, ownership labels, conformance,
  reaping, snapshots - is proven only against a fake `docker` CLI
  (`tests/fixtures/docker-backend/fake_docker.py`), which proves the
  driver's own sequencing and never a real daemon's containment boundary.
  This is precisely the live run 0.2.0 is gated on.
- **Not a real judge call.** The per-tier verdict record contract exists,
  and the judge seam itself now exists too (`skillc/judge.py`, #92) -
  schema-constrained output, a per-tier `UNAVAILABLE` outcome, a pre-send
  leak check, the disagreement record - but exercised only against a
  `FakeJudge`. The `mcp-second-opinion` adapter that would route a real
  independent-judge call, and the cost wiring a paid call needs, are not
  built; no judge call has been made against any subject. Enabling either
  needs an authorized budget first (#12) - this release does not authorize
  one.
- **Not Level 2 or beyond.** The evaluation-level ladder past Level 1 remains
  a documentation-only proposal.
- **Not a paid model trial.** No model call has been made against any
  subject as part of this work, and none is authorized by anything in this
  repository.
