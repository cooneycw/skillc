# 0.2.0

Delivers two milestones, both closed: [#10](https://github.com/cooneycw/skillc/issues/10),
a real Docker trial end to end, and [#11](https://github.com/cooneycw/skillc/issues/11),
a second independent skill collection through the same client, fixture,
contract and grader. Both were proven on the operator's own machine. Full detail: [`CHANGELOG.md`](../../CHANGELOG.md)'s `[0.2.0]`
section.

## The live run

The operator ran `skillc demo`, `skillc demo --control`, and
`skillc demo --subject` for both collections (`cpp-codex`,
`mattpocock-skills`) on native Docker Engine, Linux x86_64, at commit
`8e06030`. All four commands exited `0`; every acceptance item read `MET`;
all three seeded `--control` failures were caught; no model call was made in
any step. Full evidence, leak-checked before posting:
[the live-run comment on #10](https://github.com/cooneycw/skillc/issues/10#issuecomment-5855368984).
That comment's own facts are restated, row by row, in
[`support-matrix.md`](../specs/evaluation-facility/support-matrix.md), which
also states exactly which failure paths that run does and does not cover.

**What that run establishes, and what it does not** (the owner's own ruling,
[ADR 0005 rule 6](../decisions/0005-runtime-scope-and-cost-rulings.md)): it
proves `skillc demo`'s own scripted lifecycle proof, grading run and three
seeded negative controls on a real daemon - not an independent live re-run of every
case in the conformance table or failure-path matrix, most of which stay
proven against the fake `docker` CLI (`tests/fixtures/docker-backend/fake_docker.py`),
as accepted coverage for this milestone. The two failure paths judged most
likely to differ between the fake and a real daemon - timeout, and operator
cancellation - are tracked for a real-daemon seed under
[#122](https://github.com/cooneycw/skillc/issues/122); the rest are listed,
each with the reason it is hard to seed honestly on an operator's own
daemon, in the support matrix.

## What else shipped in this cycle

- **The Docker backend** (`skillc/docker_backend.py`, #77/#83/#85): composed
  `docker run` argv under fixed resource limits and a neutral non-root
  identity, ownership labels a cleanup sweep can find without trusting name
  matching, and a documented conformance table against `interfaces.md`'s
  required cases (#80/#87, restated post-live-run above).
- **`skillc/reap.py`** (#79/#91/#120): label-scoped, attempt-id-scoped
  container reaping (never a host-global sweep - an earlier cut of the
  interrupt-time cleanup reaped a foreign, unrelated container under a real
  `SIGINT`, and is fixed), before/after resource snapshots, and
  declared-host-path checks.
- **Four independent defects found on the operator's own first live-run
  attempt** (#118/#120, before the run that closed #10 above): an uncaught
  exception could print a raw traceback carrying the operator's home
  directory and username, including through `KeyboardInterrupt`; a fixed
  scratch path could collide across runs; the exit-code contract was
  broken; two acceptance items could read a vacuous `MET`. All four are
  fixed, each with a mutation-confirmed regression test reproducing the
  original symptom before the fix.
- **`skillc collection-run <subject>`** (#11's remaining acceptance bullet,
  "the same client, Level 1 fixture, contract and grader"): one real agent
  attempt against `evals/level1/slug-small-fix`, per declared skill
  collection, in skill-free canary mode (#26), with that collection's
  selected skills installed into the same container the agent runs in.
  Structurally unable to launch without `SKILLC_ALLOW_REAL_AGENT=1`, funded
  per ADR 0005 rule 6 (the operator's own subscription login, never metered
  spend). **Run live by the operator** (#126), once per collection, with codex-cli
  0.157.1 on the subscription login: both `cpp-codex` and
  `mattpocock-skills` were captured, with the prompt delivered, the canary
  satisfied and grading `PASS`. Evidence: [`evals/second-collection-conformance/evidence/README.md`](../../evals/second-collection-conformance/evidence/README.md). The
  live runs found four defects first (no network for the agent, a refused
  non-git workspace, a 30-second agent limit, colliding scratch paths), all
  fixed in #126. By owner ruling the agent container now runs on the bridge
  network; the grading container stays `network=none`.
- **`skillc demo --subject <name>`** (#101/#97): installs a declared skill
  collection into a real container's home, re-checks its digests
  in-container against the installation receipt, and observes the client's
  own discovery of it - proof that a collection installs intact and the
  client can see it, explicitly not that any skill is invoked, selected, or
  helps.
- **`agent_trial.py` skill-free canary mode and `skill_invocations`**
  (#106/#26): a canary instruction that names no skill, so any skill the
  agent invokes on its own is an observation, never an artifact of a prompt
  that told it which one to use - the mechanism `#11`'s harness and #26's
  own future measurement both need.
- **A credential-hermeticity fix** (#106): a test able to reach the
  operator's own real Claude subscription credential by falling through to
  its documented default location is now structurally impossible for any
  test in this suite - `HOME`/`CODEX_HOME` point at fresh empty per-test
  directories, autouse, for every test.
- **The judge seam** (`skillc/judge.py`, #69/#92): schema-constrained
  output, a per-tier `UNAVAILABLE` outcome, a pre-send leak check, and the
  disagreement record - exercised only against a `FakeJudge`. The `mcp-second-opinion` adapter
  and its cost-estimate wiring exist (#96), tested against a fake server;
  no real judge call has been made.

## What 0.2.0 is not

- **Not a full live re-proof of the conformance table or failure-path
  matrix.** Most cases stay proven against the fake `docker` CLI, by the
  owner's own ruling; see "The live run" above and the support matrix for
  exactly which rows are covered.
- **Not a measurement of whether a collection helps.** #11's live run shows
  each collection installed and the agent passing the Level 1 task with it
  present. One attempt per collection, with no baseline arm, says nothing
  about whether the skills changed the outcome.
- **Not the Claude Code agent arm.** Tracked separately under
  [#124](https://github.com/cooneycw/skillc/issues/124): a
  `claude-code-skills` surface and a per-collection Level 1 run in the
  container, for the other client this repository supports.
- **Not skill-selection measurement.** `skill_invocations` observes what a
  skill-free run invokes on its own; turning that into a measurement of
  whether a skill helps is [#26](https://github.com/cooneycw/skillc/issues/26)'s
  own job, not delivered here.
- **Not a real judge call, and not a paid model trial.** The judge seam and
  its `mcp-second-opinion` adapter (#96) are tested only against fakes; no judge call and no paid model trial
  has been made against any subject, and none is authorized by anything in
  this repository ([#12](https://github.com/cooneycw/skillc/issues/12)).
- **Not Level 2 or beyond.** The evaluation-level ladder past Level 1 remains
  a documentation-only proposal.
