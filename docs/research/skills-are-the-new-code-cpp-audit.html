Calibration report · claude-power-pack v7.5.0 · 15 Sep 2026

Skills Are The New Code

Guy Podjarny says a skill is a unit of software and needs software's five disciplines. Matt Pocock says a skill is a document and gives four levers that decide whether it fires and holds. Measured against both, claude-power-pack scores 23/45 — and the shortfall is concentrated in exactly one place.

SUBJECT · claude-power-pack @ 7.5.0 SURFACE · 18 skills · 95 commands · 23,120 lines COMPARANDS · 4
The finding

The gap is narrow and deep, not broad. CPP scores at or above every comparand on observability and supply-chain provenance, and holds its Python and shell instruments to a bar none of them attempt. It scores zero on the one discipline Podjarny puts at the centre of the keynote: there is not a single behavioural test of the 23,120 lines of command markdown that is the product. Every gate CPP owns points at the scaffolding; none points at the artifact.

Nothing on the market replaces it. Of the four serious comparands, the two that beat CPP on skill craft cover 2 of its 7 goals; the two that beat it on discipline cover none — they are graders and rails, not toolkits. There is no package to buy. There are three rails to adopt.

The cheapest fix is already installed. claude plugin eval shipped in the CLI on this machine, with a with/without ablation arm — the same measurement Tessl launched as a product. Closing the largest gap on this page starts with a directory named evals/.

Two rubrics, scored separately

They measure different objects. Podjarny grades the lifecycle around a skill; Pocock grades the document itself. A repo can pass one and fail the other, and CPP nearly does.

What each of them actually asked for

Keynote · AI Native DevCon London, 1 June 2026

Guy Podjarny — the five disciplines

The argument is not that skills should be tidy. It is that skills are code, inherit code's failure modes, and therefore need code's machinery. Skills rot; an unmaintained skill becomes harmful, not merely stale.

  • SAStatic analysis. Linting, then security analysis, then agentic review of the skill text.
  • EVEvals. Define an environment, run an agent through a task in it, judge the result. Three tiers: skill (unit), project (integration), comprehensive (end-to-end).
  • STSecurity testing. Three risk classes: malicious, negligence (urges an action, sets no boundary), vulnerable (guidance that exposes secrets).
  • DMDependency management. Registry, versioning, install/update, supply-chain visibility, quality gates, cross-agent compatibility.
  • OBObservability. Monitor agents, mine traces for new skills, extract eval scenarios from real runs.

His failure story is a shared skills repo at a large unicorn: "There are seven over here. Which one should I choose? There's no indication of which one is good." Nobody trusted the repo; everybody went back to writing their own.

Verified against the talk's own companion skill — AINativeDev/aidevcon-2026-ldn/talk-podjarny-skills-are-the-new-code (outline, quotes, transcript).
Building Great Agent Skills: The Missing Manual

Matt Pocock — the four-point sweep

Run in order over a finished skill. The organising idea is the two loads: context load falls on the model's window every turn; cognitive load falls on the human who must remember the skill exists. Every choice spends one of them.

  1. 01Trigger. Model-invoked (a description, permanently loaded, agent can fire it) or user-invoked (disable-model-invocation, zero context load, you are the index). The pointer's wording decides whether it fires.
  2. 02Structure. Split into steps and reference. Inline what every branch needs; push behind a pointer what only some branches reach. Sprawl — simply too long — is the failure mode.
  3. 03Steering. Leading words that recruit the model's priors (tight, red, deep module). Completion criteria that are checkable and exhaustive. Prompt the positive: negation makes the banned behaviour more available.
  4. 04Pruning. Single source of truth; no caching what the environment already answers; hunt no-ops (lines the model already obeys) and sediment (stale layers nobody dares remove).
Verified against mattpocock/skills → skills/productivity/writing-for-agents/{SKILL.md, SKILL-MECHANICS.md}, the maintained form of the checklist.

Podjarny

Static analysis

3ungated

scripts/skills-check.py is better than anything the comparands ship: it validates frontmatter structure, markdown links, a 200-character description ceiling, and a four-class provenance taxonomy (vendored / adapted / inspired / cpp-authored) with upstream author, source URL, licence and revision. Then it never runs. It is absent from make verify and from .woodpecker.yml. And the rule it most needs is the one it does not have: 18 of 18 skill name: values violate the Agent Skills specification.

$ make -n verify | grep -c skills-check.py → 0
$ make -n verify | grep -c check-negative-fixture → 1 (extractor works)

name: 'Code Quality' dir: code-quality
name: 'Python Packaging (PEP 621 & PEP 723)' dir: python-packaging

To move it Wire skills-check into verify and CI, add name-spec + description-shape + body-line rules, and register its known-bad case in controls/ — it is a gate that lets work through and currently has no committed negative control.

Podjarny

Evals

0no instrument

No eval case exists anywhere in the repository. The product is 23,120 lines of command markdown that instructs an agent, and not one line of it has ever been run against a graded scenario. CPP's test suite, its negative-control registry, its binary-guard contract and its detector contracts all point at the Python and shell underneath the commands. The commands themselves are ungraded.

This is the gap the repo's own directives should find intolerable: an instrument that cannot fail is not evidence, and a surface with no instrument at all is the limiting case.

$ grep -rniE "eval.?(scenario|harness|suite)|skill.?eval" scripts/ Makefile tests/
(no matches)

$ claude plugin eval --help # already installed, CLI 2.1.266
--ablation with-without run a no-plugin baseline arm, report score delta
--judge-model, --max-cost-usd, --case <glob>, --json

To move it The rail is already on the machine. Eight case.yaml files over /flow:auto, /flow:finish, /flow:wave, /cpp:init and the four *:auto delegations, run under --ablation with-without, take this from 0 to 3 and give the command surface its first negative control.

Podjarny

Security testing

3partial

Strong on the supply-chain half: provenance classes on every skill, gitleaks secret-scan in CI, classify-tool-risk.py, an output-masking PostToolUse hook, and allowed-tools declared on 54 of 95 commands. Absent on the half Podjarny spends most of the section on — the skill text as attack surface. Nothing scans CPP's own instructions for the negligence pattern (an urged action with no boundary set) or the vulnerable pattern (guidance that routes a secret somewhere visible), and the command corpus has never been red-teamed.

To move it A negligence-pattern rule in skills-check is cheap and mechanical: flag an imperative touching a destructive verb with no adjacent boundary clause. Red-teaming is the nascent half — he offers no prescription either.

Podjarny

Dependency management

2retreated

Skills carry no version. Distribution is git clone plus symlinks. CPP had a marketplace and retired it — and ADR 0005 names the structural cause in its own words: "CPP's marketplace plugin entries carried no version field… /plugin update compares version stamps, not the content behind them." The diagnosis is exactly Podjarny's discipline failing. The remedy chosen was to leave the package-management rail rather than add the field.

Credit where it is due, and it is substantial: codex/skills/ generates 75 cross-agent mirrors from the canonical command documents, drift-gated by codex-skills-check in CI. That is the "npm doesn't care if you're on Windows" goal, actually shipped — and no comparand has it.

docs/decisions/0005-retire-plugin-marketplace-distribution.md
Status: Accepted · 2026-08-11 · Supersedes ADR 0001
"24 of 98 command files stale and flow/wave.md absent"

To move it Worth a revisit, not a reversal. The failure was an unversioned stamp, and the CLI has moved considerably since August — plugin eval and plugin details both target plugin@marketplace ids. Re-entering the rail is what makes those tools addressable.

Podjarny

Observability

4best in set

CPP wins this outright. .claude/friction.jsonl is a live friction ledger; hook-permission-census.sh observes permission requests; hook-pending-retro.sh enforces the retro; /self-improvement:retro and :memory close the codify loop into a shared cpp_memory store. None of the four comparands has anything comparable.

The missing fifth point is Podjarny's third use for it: mining real traces into eval scenarios. That one is blocked purely by there being no evals to mine into — the richest input in the repo feeding the emptiest discipline.

Pocock 01

Trigger

2misplaced

Every one of the 18 skills has good trigger words. They are in the wrong field. trigger: is not part of the Agent Skills spec, so those words are never loaded; what the model sees is description:, and all 18 are capability statements — "Code review patterns, testing, and quality best practices" — describing what the skill is rather than when to reach for it. That is Pocock's central lever, pointed at nothing.

The credit is real and should not be lost: the 95 commands are correctly user-invoked and cost zero context load, and each family ships a :help router. That is precisely the router-skill pattern, built here before he named it.

--- .claude/skills/secrets/SKILL.md ---
description: Secure credential access with tiered providers… ← model sees this
trigger: secrets, credentials, database password, api key… ← model never sees this

To move it Fold each trigger: list into its description: as a "Use when…" clause, and fix the 18 names in the same pass. One afternoon; takes this axis from 2 to 5.

Pocock 02

Structure

2sprawl

The skills are right: thin routers that read one file out of docs/skills/, median 30 lines. The commands are where the sprawl is — median 138, p90 439, ten over the 500-line bar, and cpp/init.md at 2,003 lines carrying every branch inline. Being user-invoked means that cost lands per invocation rather than per turn, which is genuinely cheaper, but Pocock's point about sprawl is about attention, not tokens: it thins across the excess regardless of when it loads. 26 of 95 carry no frontmatter at all.

2003 .claude/commands/cpp/init.md
1580 .claude/commands/cpp/update.md
1423 .claude/commands/flow/auto.md
1204 .claude/commands/flow/register.md

To move it Branch-split the top four. cpp/init.md is a sequence of independent host-artifact installers — each one is a branch only some runs reach, which is the textbook disclosure test.

Pocock 03

Steering

4strong

CPP uses the lever better than any comparand and arrived at it independently. Instrument, negative control, blind, fail-open, counter-model, detector contract are leading words in exactly his sense — compact, repeated as tokens, defined once in docs/agents/glossary.md, anchoring a whole region of behaviour. The completion criteria in flow-finish-gate.sh and the ADR 0008 bound are checkable and exhaustive, which is his highest bar.

The one deduction is negation density. CLAUDE.md steers heavily by prohibition — never output, never wrap, never substitute — which he argues drags the forbidden behaviour into context. He permits it for hard guardrails, and most of CPP's are; the fix where it applies is to pair each with its positive target.

Pocock 04

Pruning

3sediment

The discipline exists and is enforced where it was aimed: claude-md-budget-check holds the always-loaded file to a budget, knowledge-graduation-check.py graduates completed specs out, and "keep one inventory item per line" is the single-source-of-truth rule stated outright. It was aimed at CLAUDE.md and not at the command corpus, which is where the sediment settled — 23,120 lines, a 2,003-line worst case, and a 109 KB changelog.

To move it Extend the budget check from CLAUDE.md to .claude/commands/** with a per-file line ceiling. The rule is already written; only its input population is too narrow.

What actually closes it

Ordered by points recovered per unit of effort. The first three are a week and take the score from 23 to roughly 33.

Give the command surface an instrument

evals 0 → 3rail installed

Create evals/ with case.yaml scenarios for the eight load-bearing commands. Run claude plugin eval --ablation with-without so each case reports the delta against a no-plugin arm — that delta is the negative control the command surface has never had, and it is the same measurement Tessl sells as Task Evals.

Move the triggers into the field the model reads

trigger 2 → 5one afternoon

Fold each trigger: list into description: as a "Use when…" clause, and fix all 18 name: values to the spec's [a-z0-9-] matching their parent directory. This is the highest-leverage edit on the page: the words already exist and are simply unreadable where they sit.

Gate the checker you already wrote

static 3 → 4

Add skills-check to verify and to .woodpecker.yml, extend it with name-spec, description-shape and a body-line ceiling, and register its known-bad case in controls/. It is a gate that lets work through, so by ADR 0008's own bound it needs a committed negative control — and today it has neither the control nor a run.

Version the skills; revisit the rail

deps 2 → 4

Add metadata.version per skill. ADR 0005's structural cause was a missing version field, not the marketplace model, and the CLI has moved since August — both plugin eval and plugin details address a plugin@marketplace id. Re-entering the rail is what makes CPP measurable by the tools that now exist.

Branch-split the four largest commands

structure 2 → 4

cpp/init.md, cpp/update.md, flow/auto.md, flow/register.md — 6,210 lines between them. Each is a set of branches only some runs reach, which is exactly the test for pushing material behind a context pointer.

Mine the friction ledger into eval scenarios

observability 4 → 5needs 01 first

Podjarny's third use for observability, and CPP is the only project in this comparison that already has the input. friction.jsonl plus the permission census is a stream of real failures with no graded destination; once evals/ exists, the retro loop can write cases into it.

Method, and what would have made this report wrong

Every number above comes from one extractor run over all six surfaces. Before it was trusted, it was run against a committed pair: a skill written to pass and a skill written to fail. It reported the opposite verdict on each, so a zero from it is a measurement rather than a silence.

bad-skill    fm=False  desc_len=   0  trigger=False  body_lines= 902  refs=0
good-skill   fm=True   desc_len=  76  trigger=True   body_lines=   2  refs=1

The two absence claims were controlled separately, because a broken extractor's zeros look exactly like real ones:

# claim: skills-check is unreachable from verify
$ make -n verify | grep -c skills-check.py        → 0
$ make -n verify | grep -c check-negative-fixture → 1   # extractor is live

# claim: 18/18 names violate the spec
$ check('code-quality',  dir='code-quality') → True
$ check('Code Quality',  dir='code-quality') → False    # rule can say yes

The Podjarny framework was not taken from conference write-ups. It was read from the talk's own companion skill in the AI Native Dev repository, which ships the outline, the verbatim quote set and the full transcript — so the five disciplines and the three risk classes are his words, not a summariser's. The Pocock checklist was read from the maintained writing-for-agents skill rather than the video, since the video's four headings have since been superseded by a longer written form.

Scores are judgement applied to measurement, on a 0–5 scale per axis. They are defensible, not objective; the measurements underneath them are reproducible and are what should be argued with.

One caveat worth stating plainly: the Podjarny score is a measure of lifecycle machinery, and lifecycle machinery is what Tessl sells. The five disciplines are a fair frame — they are genuinely the ones code has — but a single-owner repository is not the unicorn with seven untrusted skills in a shared folder, and it should not buy the governance layer that story argues for. The evals gap is real on its own terms and would be real if he had never given the talk. The registry gap mostly is not.
